# adapapavandharma.github.io

Source of <https://adapapavandharma.github.io>, the portfolio of **Pavan Dharma Adapa**.

Hand-written HTML, CSS and a little JavaScript. No framework, no build step, no
dependencies, no trackers, no third-party requests. Open `index.html` and it works.

---

## What is here

| Path | What it is |
|---|---|
| `index.html` | The portfolio: hero, five projects, experience, skills, education, contact |
| `styles.css` | All styling. Light and dark themes via `data-theme`; system font stacks |
| `main.js` | Three things: the theme toggle, the footer year, and highlighting the section in view. Deliberately tiny — its header says why |
| `dashboard/` | [`/dashboard`](https://adapapavandharma.github.io/dashboard/) — one interactive view per project, charts drawn as hand-written SVG |
| `dashboard/data.json` | Every figure the dashboard renders. A build artifact — see [below](#the-dashboard-and-datajson) |
| `resume/` | The three published résumé PDFs |
| `tools/build_ed_section.py` | Rebuilds the dashboard's emergency-department data from that project's repository |
| `tools/make-og.ps1` | An older generator for a 1200×630 link-preview image. The current `assets/og.jpg` was not drawn by it, and running it replaces that image with a different design |
| `robots.txt` | Welcomes search engines; opts out of AI-training crawlers |
| `sitemap.xml` | `/` and `/dashboard/` |

The three data and software résumés were removed on 2026-09-11. The site covers
research and health data roles only.

**They are build output — never edit them here.** Each is generated by the separate
JobSearch system from its locked facts file, converted through Word, and checked to be
exactly one page. To replace one, rebuild it there and copy the PDF in under the
**same filename**, because the hero links point at these names.

**No phone number, ever.** Anything in `resume/` is public: anyone can download it,
forward it, or scrape it. The phone goes only on the copy sent to a single employer.
Before uploading, search the PDF text for the number — the templates are meant to
exclude it, but check rather than trust. `.gitignore` blocks `*.docx`, so the source
files cannot be committed here by accident.

## The dashboard and data.json

The dashboard never hard-codes a figure. Every number comes from `dashboard/data.json`,
which has one section per project — `ed`, `denials`, `quality`, `readmission`,
`experiments` — each built from that repository's `outputs/` directory.

**`data.json` is a snapshot, not a live feed.** That distinction cost a month. The
`ed` section was built on 2026-08-05; on 2026-08-11 the ED pipeline fixed its weighted
quantiles (`774dd23`), and because the script that built `data.json` had never been
committed, nothing noticed. The dashboard's headline finding said between-hospital
variation was **3.9×** between-hour variation while every résumé said **3.56×**, until
2026-09-10.

### Rebuilding the ED section

```bash
python tools/build_ed_section.py --check    # is it stale? exit 1 if so, writes nothing
python tools/build_ed_section.py            # rebuild it from the ED repo's main branch
python tools/build_ed_section.py --ref <sha>
```

The transform in that script is a reconstruction of the lost original, and it was
**proven before it was trusted**: run on the outputs at `3b1e28a`, the commit the
dashboard was first built from, it reproduces the 2026-08-05 section with zero
differing values. It rewrites only the `ed` section. The file is written back in the
format it was created in — compact, ASCII-escaped, no trailing newline — so the other
four sections stay byte-identical and a rebuild diffs only what changed.

### The other four sections

They have **no generator**. On 2026-09-10 each was verified current: none of the
denials, quality-measures, readmission or experimentation repositories has changed a
value in `outputs/` since the dashboard was built. (The quality-measures fix on
2026-08-11 changed code, not results.)

If one of those repositories does change its outputs, that section needs rebuilding.
Write its generator then, and prove it the same way: reproduce the current section
from the old outputs first, and only then run it on the new ones.

## Keeping the page in step with the résumés

Every figure on this site must match the résumés, the LinkedIn profile and the GitHub
profile exactly — a recruiter comparing two surfaces should never find two numbers for
the same work. The source of truth is the JobSearch system's `facts.json` and
`projects.json`. When a figure changes there, all of these change with it:

- the four **stat tiles** under the hero — static markup in `.proof` in `index.html`
- the **Experience** bullets, which are copied from the résumé bullet text
- the five **project cards**
- `<title>`, the meta description, the `og:` tags and the **JSON-LD** `Person` block in `<head>`
- `dashboard/data.json` (via `tools/build_ed_section.py` for the ED section)
- the PDFs in `resume/`
- `lastmod` in `sitemap.xml`

The nano16s pull-request count is the one that moves. It went 30, 32, 34, then 36
between 2026-08-26 and 2026-09-10. Check it against GitHub before quoting it anywhere:

```bash
gh api "search/issues?q=repo:lz245/nano16s+is:pr+is:merged+author:adapapavandharma" --jq .total_count
```

## Deploying

Pushing to `main` deploys through GitHub Pages (**Settings → Pages → Deploy from a
branch → `main` / root**). It is usually live within a minute. To watch a build:

```bash
gh api repos/adapapavandharma/adapapavandharma.github.io/pages/builds --jq '.[0].status'
```

`.nojekyll` is present, so Pages serves the files as they are instead of running Jekyll.

## Local preview

```bash
python -m http.server 8000
```

Then open <http://localhost:8000>. `index.html` also works straight from `file://`, but
the dashboard needs a real server: it is an ES module and loads `data.json`, and
browsers block both over `file://`.

## Accessibility and performance

- Semantic landmarks, a skip link, and visible `:focus-visible` rings
- Light and dark themes. The first visit follows `prefers-color-scheme`; the toggle
  then persists the choice in `localStorage` (`pda:theme`), and a two-line inline
  script applies it before first paint, so there is no flash of the wrong theme
- Respects `prefers-reduced-motion`
- System font stacks only — no webfont requests and no layout shift from a font swap
- The portrait is served through `srcset` (800w / 1400w)
- `noai` / `noimageai` meta on both pages, alongside the crawler opt-outs in `robots.txt`
- No third-party requests at all: the charts are hand-written SVG, with no chart
  library and no CDN

## What is gone, and why

Until 2026-08-26 this site had a track switcher (`?track=epic` / `?track=analytics`),
a typed-text hero, a command palette, animated counters and a scrollspy. A single bad
selector in the scrollspy threw, which stopped every script after it and took the page
down. The rebuild removed all of it and made the page deliberately static, which is why
`main.js` is short and guards everything it does.

The Epic framing went at the same time. Pavan is not Epic certified — certification
requires employer sponsorship — and the Skills section says so plainly.
